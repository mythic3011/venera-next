# Contributing and issue policy

This repository is not a feature-request queue. Issues and pull requests should
be actionable and aligned with the canonical runtime direction.

## Bug reports

Include:

- reproduction steps
- expected and actual behaviour
- affected platform and version
- logs or structured diagnostics where relevant
- a concrete proposal when suggesting a fix

## Design proposals

Breaking changes are allowed. A proposal that preserves a fragmented legacy
storage or runtime model should explain its migration path and why it does not
block the canonical data model.

Before opening an issue or pull request, read the relevant [active design
document](design/SUMMARY.md) and include the verification commands used.
